## Two future targets (frozen now)

Motivation: subsequent system integration can require additional setup or hold margin. Preserve clock period, clock waveform, part, all I/O/exception settings and tool version. Do not shorten 1.570 ns: the source XDC comments identify a 1.569 ns BRAM minimum-period limit; this is a source comment, not independently verified silicon evidence.

G1: user setup uncertainty 0.050 ns on the sole primary clock, preserve the original hold user uncertainty. G2: user hold uncertainty 0.060 ns, preserve original setup user uncertainty. These are explicit absolute user-uncertainty values, not additions to an already nonzero user value. Gate requires original user uncertainty zero and exactly one primary clock; otherwise STOP and revise before collecting outcomes. Two targets get equal weight. They represent two margin assumptions, not an empirical distribution of future customer requests.

AMD 2025.1 UG835 documents setup/hold-specific `set_clock_uncertainty`: https://docs.amd.com/r/2025.1-English/ug835-vivado-tcl-commands/set_clock_uncertainty . It adds user uncertainty to tool jitter, without redefining clock edges. The 2026.1 methodology note warns that hold margin can create unfixable dedicated-path violations: https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Additional-Uncertainty . Confirm behavior and dedicated-path feasibility using installed 2025.1 help and reports before experiments. If a target is structurally impossible under fixed primitives, report that gate failure and stop; do not silently replace it with an outcome-favorable target.

## Frozen continuation protocol

One pair x two targets is the existence gate. Each continuation starts in a fresh process from the selected state, installs its target and uses the SAME fixed panel: A0 no-op; A1 Default phys_opt; A2 Explore phys_opt. Applicability and route-completion work frozen once for both states and targets before any outcome. No resynthesis, unplacement/replacement or hidden reset to original, since that changes the question. All diagnostic/report/completion costs count. Three separate attempts per state-target-action (technical repeats, NOT independent designs), randomized interleaved order with selection RNG seeds 4101,4102,4103. No invented Vivado seed: log tool randomness as uncontrolled unless an installed supported option is demonstrated.

Budgets B1=60 and B2=120 seconds per action process. Common panel allowance 3*B per state-target-repeat; separate timeouts start afresh, B2 results are not retroactively substituted for B1. Timeout is censored/failed validity, not successful zero utility. Process-start, target-install, action, completion and reporting times recorded separately. Future target, state creation, current matching and continuation costs remain separate ledgers. Tool-start failure is infrastructure failure; preserve it and permit only one logged identical infrastructure retry. No action fallback.

Report per-goal best VALID observed WNS/TNS, WHS/THS, endpoint failures, DRC/route status and cost; also report the full panel and no-op changes. G1 compares setup WNS subject to no new hold violation relative to its own constrained no-op. G2 compares hold WHS subject to no >0.020 ns setup WNS degradation relative to its own constrained no-op. Physical resource counts and correctness must still pass. Report absolute timing closure separately; baseline setup failure makes a pure closure-rate metric susceptible to a zero floor. Do not combine setup and hold in an arbitrary scalar optionality score.

Use paired state gaps and within-state repeat spread. H1 candidate requires a >0.020 ns relevant slack gap exceeding twice the maximum within-arm repeat range, same direction in all three repeats, with validity and secondary gates satisfied. This is a descriptive prepilot decision threshold, not statistical significance from n=3 or population evidence. No pooled p-value over correlated endpoints or seeds. If all fail, tie, or gaps are below threshold, retain null result.

## Claims and stop rules

H1: one independently confirmed pair may establish an existence example of different achieved future performance under this finite protocol. Discovery panel is not confirmation; rerun fixed selected pair and targets without retuning, then seek a separately constructed pair/design family.

H2: matching and repeats reduce obvious confounding but one pair cannot establish effects beyond all current features. Require an independent design family, more matched pairs and predeclared covariate/ablation analysis before this claim. If difference disappears at B2, changes sign, or vanishes under a separately frozen stronger searcher, report protocol/budget dependence, not lost inherent reachability.

H3: NOT tested here. It needs a separately frozen selection rule, observable current features and held-out future objectives/designs; choose before observing future evaluation, compare to greedy current QoR at matched total cost. Oracle finite-panel preference change is insufficient evidence of an online agent.

Stop if no matched pair; unknown functional correctness; hidden netlist/clock/constraint differences; lack of legal common actions; target structurally infeasible; resource or timeout imbalance; all action results invalid; effect within repeat spread; or reset-heavy action erases state history. Alternative explanations retained: initial endpoint slack distribution, routing/congestion, current unmeasured features, synthesis changes, route-completion differences, user-uncertainty semantics, tool nondeterminism, startup censoring, engineering relevance of margin assumptions and finite search weakness. Null results narrow this protocol; they do not prove absence of all future value.
