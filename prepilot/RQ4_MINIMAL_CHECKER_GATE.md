## Limited correctness claim and physical-action premises

Under the premises that (a) the original DCP is accepted as the functional reference, (b) the complete relevant logical semantics are serialized in the compared EDIF, (c) identical primitives are interpreted identically, and (d) physical realization passes the vendor placement/routing/DRC/timing contract, exact unchanged EDIF supports the narrow statement **no serialized logical-representation change was observed**. It is not independent end-to-end functional equivalence. No full-spec, unconstrained-I/O or bitstream/hardware proof is claimed.

Restrict candidate/continuation actions to a common source checkpoint and fixed device/clock/constraints; reject any output with changed EDIF bytes, clocks, exceptions or resource semantics. No retiming, resynthesis, LUT remap, logic/clock replication or manual netlist editing. Generic phys_opt directives are NOT promised physical-only. They may be tried only within parent-authorized RQ1 scope and accepted after checks, not assumed safe beforehand. Prefer a genuinely placement/routing-only action if installed command help and before/after evidence establish it, but no such exact action has yet been frozen. If available outputs all change EDIF, stop this low-cost gate rather than build a full equivalence framework.

On RQ1 outputs, first perform the cheap archive byte screen and current-only matching without any new Vivado run. If a candidate has reordered EDIF but perhaps unchanged semantics, conservatively reject it from this gate and record the limitation. This trades false rejection for a small, reviewable correctness scope. No unsupported parsing or automatic canonicalization.

Candidate selection and current matching remain the fixed first-passing rule from v0. No pair accepted yet. Goal for this small gate: can a matched pair be found and can a fixed legal physical continuation respond to this hold pressure while retaining logical representation and setup quality? Once the parent accepts a pair and selects one legal continuation using installed-help/current-only information, a possible first feasibility dispatch is at most six fresh processes: each of two states gets (1) target no-op, (2) continuation under original constraints then re-score under target, (3) continuation with target installed before optimization. This retains the essential controls without a full panel, second target, two budgets or three-repeat batch. A 120-second cap per process gives <=12 minutes process wall plus declared checking overhead. No run is approved here. One attempt cannot support a noise-exceeding H1 claim; repeat/confirmation is a later decision only if feasible and informative.
