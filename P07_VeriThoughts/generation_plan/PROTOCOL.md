# Frozen minimal real generation/check/feedback plan v1

Status: plan only. No live call, budget change, configuration readout or model deployment. Parent centrally allocates a NEW batch before execution. Existing batches are not reused. This protocol supersedes the earlier infeasible USD 0.25 proposal; the public shared quote reserves USD 0.32 per <=2048-output, reasoning-disabled request. Maximum three attempts require a USD 0.96 reservation ceiling within the project's shared cumulative USD 10, not an additional paper budget. Actual successful provider usage settles via the same ledger; failed/unknown requests retain their conservative reservation. Estimated attempts: one if initial success, three if initial scientific failure; no credible exact expected dollar estimate is available before measured usage. Do not label 0.96 as an expected bill.

## Request and check sequence

1. Verify old CPU results, exact source/runner/input hashes and new frozen plan hashes; acquire project file lock. Parent verifies new batch authorization, remaining global balance, request allocation >=3, per-request output cap >=2048, central model, and zero unresolved reservations. Never print configuration or inspect its private fields. A central mismatch is a stop, not an invitation to edit policy.
2. Fresh-process import public shared Client, load_config, conservative_chat_quote. Build system+user text from plan.json and the exact Q. Before any request, quote full messages, require <=24576 serialized bytes with no context truncation, require quote <=0.32 and cumulative attempt reservations <=0.96. Invoke only `Client(load_config()).chat(messages, project='verithoughts', run_id=<unique fixed-stage label>, max_tokens=2048, max_cost_usd=0.32, authorize_live=True, request_options=plan['options'])`. This action remains disabled until parent allocation; the thread does not self-enable it.
3. Parse with the original evaluator's reason-mode CODE BEGIN/CODE END parser and fallbacks. Save candidate, full response and hashes before checking. Use the same pinned upstream full entrypoint and Yosys 0.41 from the CPU pilot in a fresh stage result directory: one response, original sample's ground_truth, `--reason_mode`, `--samples_per_question 1`. Preserve its 150-second module timeout and 50-step zero-init script. Ignore invalid pass@5/10 console values. Read written label and nested subprocess logs. Also report the additional nonempty candidate/discovery guard. A length-limited completion remains a real failed/truncated attempt; do not silently resample it.
4. If initial candidate passes, stop after one request and report no failure/repair opportunity. Do not inject corruption or claim feedback superiority. If checker infrastructure fails, times out or produces ambiguous results, stop unknown and do not feed an infrastructure diagnosis as a scientific error. Transport/protocol failure also stops without retry and requires central ledger reconciliation.
5. If initial candidate receives a genuine bounded counterexample, syntax rejection, absent required module or empty parsed candidate, freeze both follow-up message hashes before either call. Run no-feedback arm FIRST: a fresh independent conversation containing exactly original system, original Q and the fixed no-feedback retry instruction, with no initial output or result. Then run feedback arm in a separate conversation containing original system, original Q, initial assistant response and fixed feedback template. No feedback-arm result can influence baseline. Run each once with identical model/settings/output cap/reservation. Check each with step 3; stop after these two regardless of results.

The feedback category is deterministically one of bounded_counterexample, syntax_error, missing_module or empty_candidate, justified by retained logs. Feed at most 4096 characters of diagnostics: first 2048 and last 2048 characters of the selected raw Yosys stdout+stderr, marked as an excerpt when longer. No golden source or stored candidate is included. This clips diagnostics explicitly, not the specification or full conversation; if complete messages exceed the transport bound, stop instead of dropping context. A failure with no justified category stops unknown. Do not substitute a hand-written suggested implementation for checker feedback.

## Matched comparison and report

Each trajectory consists of the SAME initial generation plus one second attempt: two calls and 4096 maximum visible output tokens per trajectory. The initial cost is shared, so only three unique requests are billed. Each trajectory has a counterfactual reservation ceiling 0.64 USD; actual unique batch ceiling is 0.96 USD. The feedback arm necessarily has longer input context; input tokens and realized cost are NOT exactly matched. Report this explicitly with actual provider token/cost usage. This matches request count and output opportunity, not total text tokens or actual dollars. No early stop after baseline success: if the genuine-initial-failure branch was entered, both fixed second attempts run unless a safety/accounting/infrastructure gate stops execution.

Report initial/second candidate labels, guarded labels, failure categories, finish reasons, request/parse/check statuses, raw hashes, elapsed/check CPU, token usage and actual/reserved cost. Primary closure criterion is an auditable genuine failure -> actual checker feedback -> checked fresh revision, with independent no-feedback comparator. Repair success is an observed transition, not guaranteed or required for honest closure. With n=1 and failure-conditioned comparison, no aggregate pass@k, significance, unbiased general improvement rate or feedback-superiority claim is supported. No expansion or post-outcome prompt tuning.

## Correctness boundaries

The exact benchmark has zero golden empty discoveries in 291/291 inventoried rows; the zero-check acceptance was observed ONLY under deliberate malformed-gold fault injection. This experiment keeps row 1 golden bytes fixed, so it does not treat that injected defect as a model-output or benchmark corruption rate. A guarded pass still means only bounded agreement after original preprocessing under zero initialization and default parameters. It does not prove unbounded sequential equivalence, arbitrary reset/initial states, question completeness or reasoning correctness. The full original checker validates every discovered corresponding module; a top-only rewrite that omits required helpers is outside its contract. No induction/horizon change or simulation substitutes for its labels.

CPU: APRIL, one available affinity core, dedicated existing venv/toolchain and per-process 4 GiB address-space limit; no GPU. At most three candidate evaluations, each row contains one module; maximum 450 seconds nested waits plus orchestration. Do not repeat old controls or the 32 frontend checks. Preserve first failures and raw responses privately. No public push/PR; parent reviews specific new payload before publication.
