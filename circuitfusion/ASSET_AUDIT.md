## Paper evidence and mechanism

The [official paper](https://proceedings.iclr.cc/paper_files/paper/2025/file/7ffb43adf37b3eeaba559098bc084cc6-Paper-Conference.pdf), §§3–4 and Appendices B–D, describes register-boundary cones with HDL, operator-graph, and functionality-summary modalities; unimodal encoders and cross-attention fusion; equivalent transformations; masked/contrastive learning; and auxiliary RTL–netlist alignment. Retrieval uses known circuits' metrics. It reports 41 parent designs, 7,166 aligned original pairs, 57,328 augmented subcircuits, and an 80/20 whole-design split (33/8). Labels use Design Compiler `compile ultra`, NanGate45, and PrimeTime. Summary generation is called GPT-4 in the main text and GPT-4o in the appendix. The code encoder is frozen NV-Embed-v1. Reported infrastructure is four A4000 GPUs and 512 GB host RAM; 50-epoch training is described as 10 hours on four GPUs or 32 hours on one, while another passage says approximately 20 hours. These are author reports, not verified runtime or minimum requirements.

## Static implementation findings

These are observations of the public source, not executed failures or evidence that the published experiments used these settings.

1. **HDL fusion differs by path.** [model_pretrain.py](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/model/ckt_fusion/models/model_pretrain.py), lines 125–147, overwrites `alpha` to zero before inference fusion. Code embeddings are calculated but excluded from fusion; MLM mixup also sets zero. Matching training instead mixes at 0.5 (lines 251/256). The class instantiates `TripletLoss`; [loss_fn.py](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/model/ckt_fusion/models/loss_fn.py) implements a Euclidean margin triplet objective. Do not call this published-result invalidation: the release may contain experimental/ablation settings.
2. **Documented summary-vector script is incomplete.** [summary2vec.py](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/data_collect/rtl/rtl2summary/summary2vec.py), lines 49–54, exits before pickle output. It opens summaries with `.v` while the summary generator writes `.txt`. This is a verified static integration inconsistency. Its 1024-token setting also should not be mistaken for a verified long-context code-embedding pipeline.
3. **Gradient accumulation needs repair or explanation.** [pretrain_align_all.py](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/model/ckt_fusion/pretrain_align_all.py), lines 89–102, steps/clears gradients every batch, then steps again every 128 batches. Thus the visible loop does not accumulate 128 batches. The same file forces GPU index 0 and 50 epochs. No numerical effect measured.
4. **Pairing is positional.** The [loader](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/model/ckt_fusion/dataset_proc/load_dataset.py) reads separate modality files with `shuffle=False`; the entry point combines eight loaders with `zip`. That requires identical order and length; `zip` silently stops at the shortest. Text negatives use an independently shuffled loader. No explicit sample-ID join or equality assertion was visible in these inspected paths. This is a testable integrity risk; actual mismatches are unverified.
5. **Preparation depends on author-local paths.** [Context splitter](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/dataset/dataset_context/split_train_valid.py) loads cached token outputs and pooled embeddings, but drops stored token attention masks from its active representation. It filters by summary-file presence. Missingness and padding effects require measurement. [Netlist transformation script](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/data_collect/netlist/dataset/scr_net2graph/transform_net.py) selects negatives from a global design list, so split-before-negative-mining must be verified.
6. **Environment specification needs reconstruction.** [requirements.txt](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/requirements.txt) is a Linux Conda export with Python 3.9.18, PyTorch 2.3.1/CUDA12.1, DGL 2.4.0+cu124, flash-attn 2.0.2 and pip-origin `pypi_0` entries. The current Python is 3.12. [Issue #1](https://github.com/hkust-zhiyao/CircuitFusion/issues/1) reports Conda package-resolution errors. Compatibility is untested; do not promise the README install command works.

## Minimum faithful module and proposed future pilot

The minimum useful unit is a register cone with **all three RTL views and an explicitly matched synthesized netlist view**, a small encoder per view, cross-attention fusion, and an RTL–netlist contrastive objective alongside at least one within-RTL objective. Omitting the netlist stage would lose the central synthesis-alignment claim. A handcrafted score-only demonstration would not test representation learning.

Proposed bounded budget, not measured requirements: 8–12 independent small parent designs; 100–500 cones total; two verified equivalent RTL variants per cone; cap HDL at 512 tokens and graphs at 128 nodes; 64–128-dimensional embeddings; small trainable text encoders, graph encoder and fusion layers. Plan 4 CPU cores, 8–16 GiB RAM and under 2 GiB generated artifacts, with a stop budget of one CPU-day for data preparation plus a small training smoke study. An optional 12–24 GB GPU would expand the budget, but is not currently available. CPU feasibility is provisional: preprocessing support, convergence and sufficient statistical power are untested. Do not extrapolate pilot runtime to the original architecture.

Use self-authored or clearly licensed compact RTL and human-reviewed functional summaries initially. With future authorization, Yosys/ABC can produce equivalent variants and mapped netlists against a separately verified open cell library. Preserve register names or generate an explicit provenance map; do not assume synthesis preserves them. Keep tool version, cell library, clock constraint, variant seed, parent ID, endpoint ID, checksums, and modality lengths in one manifest. Generate variants and negatives only after assigning parent-family splits; place all VexRiscv/Chipyard configurations and near-duplicate families together where appropriate. Require all modality IDs and counts to match before batching.

**One useful mechanism test:** compare correct RTL–netlist pairing against parent-stratified shuffled pairing and no alignment, with identical data, modalities, losses, seeds, and model size. Evaluate held-out-parent RTL-to-netlist Recall@1/5 and embedding stability under equivalent HDL transformations; give bootstrap intervals over parents, not cones. Remove names/comments or anonymize consistently as a shortcut control. A useful result is reproducible improvement over shuffled pairing; no improvement is a concrete gap worth investigating. No such test has been run.

| Substitution | Preserved | Semantic loss / limitation |
|---|---|---|
| Small text encoders instead of NV-Embed | Independent code modality, projection and fusion | Loses pretrained 7B semantics and long-context coverage; cannot substantiate original scale/performance. |
| Human-checked summaries instead of API generation | Functionality text paired to HDL | Loses original summary distribution; author knowledge may simplify the task. Track summary provenance and permit blinded review. |

## Testable gaps and decision gates

Potential weaknesses, not verified errors: parent-family similarity may make a nominal whole-design split easier; functionality summaries may rely on identifiers; repeated cones may inflate effective sample size; synthetic-equivalent transformations may not preserve register correspondence under retiming/merging; semantically similar circuits may have different timing under load/constraints; retrieval can transfer technology/constraint-specific labels. The regex-based [cone extractor](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/data_collect/rtl/dataset/cone_extract.py) warrants signedness, bit-width, reset, multi-clock and normalization checks before general HDL support is claimed. The [positive transform](https://raw.githubusercontent.com/hkust-zhiyao/CircuitFusion/main/data_collect/rtl/dataset/pos_transform.py) uses a small fixed Yosys optimization sequence; broad augmentation diversity is unverified.

**L2 is provisional and applies only to this small substituted mechanism route.** Code exists and small-tooling/data/training gaps appear bounded; the current environment can inspect assets but cannot run even that route as configured. Confirm suitable licenses, a working read-only source download path, installable parser/synthesis stack, and a small pairing manifest before authorizing a pilot. Stop early if cone alignment or CPU budget fails.

**L3 applies to full results.** Rebuilding the benchmark and synthesis labels, obtaining commercial DC/PrimeTime access, resolving missing artifacts, managing the gated ~15.7 GB backbone plus caches, and training materially exceed cheap CPU-only completion here. Commercial costs and GPT summary token costs are unknown; no quote or endpoint entitlement was checked. Existing released paired data, cached embeddings and checkpoints could reduce the level, but were not verified. Reported 512 GB host hardware is not a proven minimum.

No pending execution approval exists. Remaining blockers are metadata/network visibility and asset/resource availability, not a failed experiment. Audit complete; no further paper audit started.
