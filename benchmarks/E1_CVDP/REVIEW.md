## Claims, mechanisms and release reconciliation

The paper describes 783 retained tasks from 1,313 authored tasks, 617 non-agentic and 166 agentic, in 13 categories. About 35 experienced engineers wrote the tasks; expert and model review filtered ambiguity/consistency. The mechanism is small oracle-context repositories plus per-task simulation, lint/synthesis, or text scoring. Docker isolates tools and agent execution. This is a benchmark mechanism rather than a new RTL synthesis algorithm.

The best reported aggregate non-agentic generation score is 33.56% (rounded to 34% in the abstract); GPT-4.1 is 28.91%. These are paper claims, not measured here. Crucially Section 4 says agentic datapoints were **converted to single-turn non-agentic evaluation**. Table 3 therefore does not establish gains or losses from interactive tool use. Task population, context length and difficulty differ between tables.

The current five ordinary files contain **772 tasks**: non-agentic generation OSS 302, commercial 187, comprehension 123; agentic OSS 92, commercial 68. These counts must not be reported as the paper's 783. The README says 20 initial omissions due to harness/licensing issues; the changelog adds 9 generation tasks in v1.0.1, consistent with 783−20+9=772, but a full task-level paper-snapshot join is unavailable. Five released examples with solutions were removed from additional datasets according to the changelog. They are calibration examples, not independent held-out samples.

v1.1.0 updates cocotb/pytest/tool versions and recalibrates fan-controller, VGA-controller and GCD thresholds. v1.0.3 fixes PISO; v1.0.4 fixes pinning. The v1.1.0 README quick-start commands still name v1.0.1 example files, while the checkout contains v1.1.0 filenames: follow actual pinned files. New heavy-context tasks are an extension, not the paper's oracle-context protocol.

## Evaluator and leakage audit

1. **Oracle context:** Paper Sections 2.1 and 6 explicitly supply minimal relevant files. Scores do not test repository discovery, retrieval, integration with unseen modules, or the full hardware lifecycle.
2. **Reference availability:** All 649 ordinary generation records have empty reference-code/patch payloads, despite nonempty dictionaries naming expected output files. A dictionary-presence test would falsely report references as available. Comprehension responses are present. Official solution examples cover only one OSS non-agentic and one OSS agentic problem.
3. **LFSR example, static concern:** `cvdp_copilot_lfsr_0001` checks one transition and compares first/last DUT handles, without collecting 255 distinct nonzero integer states. For a constant-zero design, the asserted transition equation yields zero and the handle equality is vacuous. Independent arithmetic confirms that zero violates the nonzero-seed behavior (seed 153 should next produce 253). **Observed:** after approved transfer, the constant-zero implementation passed all three upstream cocotb tests. A separate specification assertion rejected it on seed loading; reference and vector-equivalent implementations passed that independent assertion suite. This demonstrates false acceptance in this released example, not the whole benchmark.
4. **Arbiter example, static inconsistency:** `cvdp_agentic_fixed_arbiter_0001` specifies a single highest-priority override bit, while the supplied reference assigns the full override vector. Override 3 yields two grants instead of the specified one. The example's test supplies only one-hot overrides, so it cannot distinguish those behaviors. Also examine asynchronous reference reset against synchronous wording before using it as truth. **Observed:** the supplied reference passed the upstream test but failed a separate multi-hot override assertion. A one-hot-override alternative passed both suites for the tested behavior; reset synchrony remains unresolved. The no-override mutant failed the upstream assertion. The extra-wire variant and reference were accepted; the duplicate multi-hot label intentionally uses the same reference source and is not an independent solution.
5. **Explicit answer-exposure flags:** `src/dataset_processor.py` can write `golden_ref_solution.patch` when `include_golden_patch` is enabled and can include harness files. `src/wrapper.py` exposes force-agentic inclusion options. Freeze these false for evaluated agents; never use quality-refinement contexts containing full datapoints as evaluation prompts. Availability of a dangerous diagnostic option alone is not proof default runs leak.
6. **Metric:** `run_reporter.py:666` uses `1−(1−c/n)^k`. At k=1 this equals c/n, consistent with the paper's n=5 pass@1 estimate. For k>1 this differs from the without-replacement estimator `1−C(n−c,k)/C(n,k)` (n=5,c=1,k=2: 0.36 versus 0.40). Do not inherit pass@k claims from that reporter. Five stochastic draws need uncertainty reporting, per-task denominators and retained infra failures.
7. **Correctness:** Parse cocotb testcase XML and failed assertions plus process outcome; a printed PASS or successful outer process is insufficient. Mutation controls and independent truth tables should establish that the harness exercises semantics. Finite simulation cannot prove all parameterizations or temporal behavior.

## Prior-work boundaries and useful principles

The paper explicitly builds on SWE-bench-style repository/harness evaluation. VerilogEval/RTLLM already evaluate spec-to-RTL; RTL-Repo supplies repository-derived completion; LLM4DV covers stimulus; OpenLLM-RTL includes assertion-related evaluation. CVDP's defensible distinction is coverage, expert authorship, curated contexts and extensible agent infrastructure. Broad claims of being the first hardware agent benchmark need task/protocol qualification. The paper's own agentic infrastructure is not evidence of actual interactive-agent performance.

A trustworthy EDA benchmark should pin each data/tool release; separate calibration from inference; test no-op, malformed, valid-wrong and equivalent solutions; hide evaluator/answers from agent mounts; test resets, parameter boundaries, temporal coverage and multi-hot corner cases; preserve all selected-task failures; report commercial coverage separately; and compare modes on identical tasks/context/model with declared budgets. LLM-derived failure clusters and subjective scores require independent validation and cannot establish causal explanations.

## Bounded runtime outcome

All eight frozen tasks received no-op and invalid controls. Eight invalid implementations were rejected; seven no-ops were rejected (missing code/ports or semantic assertion), while the cid007 cont_adder_0042 no-op passed four simulation tests. Follow-up exact Verilator 5.038 lint rejects that no-op with original fatal warnings, so the combined task fails; positive reference acceptance remains UNKNOWN. Both official OSS example references passed the original harness. Independent GP truth-table and equivalent carry implementations passed, while the XOR-propagate mutant failed. Initial 26 launches failed before simulation because the minimal sandbox lacked /bin; all were retained and repeated in a new output directory after adding a namespace-local /bin→usr/bin symlink. The repaired run has 26 variant launches and six missing-reference records; five separate semantic assertion executions plus one alternative upstream replay supplement it. No timeout occurred. Selection and mutation results are evaluator controls, not stochastic model samples or pass@1 estimates. Raw evidence including candidate/hidden-test files remains private; published-safe summaries contain only metadata and outcomes.

The lint follow-up adds no performance claim: original flags/config and pytest test_lint were preserved, with no-op warning rejection and invalid syntax rejection confirmed from diagnostics. It closes the missing lint execution component only. See LINT_DELTA.md for the incremental evidence requiring independent delta review.

Audit clarification: arbiter supplemental assertions test the multi-hot override requirement only. They do not test or resolve the synchronous-specification versus asynchronous-reference reset mismatch. Full specification conformance of the alternative is not established.
