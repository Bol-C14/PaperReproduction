# Bounded evaluator validity pilot

This is a purposive, falsifiable mechanism experiment on four independent designs, not a new model evaluation or an estimate of corpus-wide false-positive rates. The frozen plan and its hashes were committed as `3f4ab0c` before execution. The 63 primary trials cover GA94, address_mux, mux4, and combinational USB CRC16. The prior 108 reference calibration passes remain calibration, not independently established correctness.

## Findings

* **GA94 unchanged official comparator:** identity passes. Seven functional output mutations actually change outputs on all 1,217 recorded DPI calls. Only `egg_xor_1` fails; six activated mutations survive: value XOR1, value XOR128, sign inversion, egg XOR2, egg XOR4, value stuck255. Value stuck0 changes nothing in this workload and is excluded from activated fault evidence. All completed runs report 101 official checks. This confirms the previously isolated scalar/concatenation comparison blind spot under the substituted DPI environment; it does not establish historical paper scores. The official comparator was not repaired. Malformed C++ fails compilation; nonterminating C++ times out at three seconds and is unknown, never functional fail/pass.
* **TBGen address_mux:** a 64-vector binary relation checker catches five deterministic DUT faults on both simulators. Empty TB has no checking evidence and is unknown. Replaying the pinned upstream generic `VCSRunner.run_simulation` method on the actual captured free-simulator logs accepts all of these failed/empty runs: its error regex does not recognize `TEST_FAIL`, and return-code zero plus no recognized error is sufficient even without a pass marker. This is a concrete parser contract weakness in the pinned code/log combination, not a VCS run or proof that all paper-generated TBs use this marker. No upstream predicate was modified. The strict adapter preserves counts and explicit failure priority.
* **RTLFix mux4:** corrected baseline passes both official six tests and an independent exhaustive Boolean mux oracle over all 64 binary inputs. The original bug and three broad functional faults fail both oracles. An all-zero-input exception passes all six official tests but fails the independent oracle at input `000000`, on both simulators. This is a demonstrated local coverage gap in the supplied testbench, not a claim about the complete benchmark.
* **SVAGen CRC16:** a source-derived single-bit assertion catches bit5 inversion/stuck0 but misses bit4 inversion and the bit15 XOR-to-OR fault. Sixteen source-derived output properties catch all four faults. These proofs measure property scope and mutation sensitivity; source-derived equations are not independent specifications. Constant-true assertions prove on both correct and covered-mutant DUTs, so their raw `pass/proven` is retained while **adequacy is unknown**, never reported as an adequate verification solution. Empty property set has actual zero assertions and is unknown. Malformed property syntax fails. Property counts come from the emitted Yosys JSON, with actual solver logs and counterexamples retained.

## Compatibility correction and evidence selection

The first 14 TBGen trials used SystemVerilog `$random(seed=13579)`. Icarus and Verilator produced different random sequences despite the common seed. Decisions agreed but some failure counts differed, so that first execution cannot support identical-input equivalence. A bounded compatibility correction replaces only vector generation with a Python-seeded literal 64-vector table; mutations, expected relation, checks, seed and sample size are unchanged. Only those 14 trials were retried. Their original logs remain in `pilot_1`; `tb_vector_repair` contains the replacement evidence and vector table. `selected_trials.csv` explicitly chooses these rows. The resulting 19 backend pairs comprise 18 pairs with actual checks (6 TBGen plus 12 RTLFix oracle/candidate pairs), whose input RTL/TB hashes, decisions and failure counts agree, plus one empty-TB control pair with matching unknown decisions and null check/failure counts. The empty control is not evidence of successful functional checking. This applies to binary, combinational, timing-settled cases only; it does not validate X/Z, race, delta-cycle, four-state or temporal semantics between tools.

## Budget and execution

See `metrics.json` for measured totals: 63 primary trials, 14 compatibility retries, 77 actual trial executions; no new designs or outcome-driven mutations were added. The combined total is 142 supervised commands. The two round elapsed durations sum to **154.043 seconds**, below the preregistered 840-second budget. The sum of recorded subprocess durations is approximately **181.443 seconds**; subprocesses overlap because execution uses up to two workers. Neither number is CPU time, and summed round elapsed time is not cumulative process duration. All raw outcomes, tool feedback, source mutations, unified diffs, activation counts, actual property counts and process events are retained. Rebuildable binaries and waveforms are omitted from the source archive. A raw successful proof is distinct from adequate checking; no missing 265 original cases have been invented, and the 482-directory coverage matrix is unchanged.

## Isolation boundary

The subprocess environment is an explicit allowlist with synthetic credential-canary absence verified. Existing syscall filtering rejects network socket creation, ptrace and namespace/mount operations; process groups, wall timers and CPU/address-space/file/FD limits are applied. The recorded probe verifies 2 GiB address space and 8 MiB file limits. **There is no filesystem confinement:** the deliberately synthetic sibling canary is readable and writable. No claim is made that this runner safely handles arbitrary untrusted submissions. Only manually reviewed, pinned official source and these fixed recipes are in scope; no credentials are inherited. This round did not change host security, namespace, network or credential configuration. A disposable credential-free filesystem/container environment remains required before expanding to arbitrary model-generated code. Free Icarus/Verilator/Yosys installations were reused; no paid tools or APIs were invoked.

## Reproduction and offline verification

From repository root, after the existing `fixme/REPRODUCTION.md` setup, run:

```sh
python3 fixme/benchmark/validity_round.py --upstream .cache/fixme/upstream --tools .cache/fixme/tools --output /tmp/new-fixme-validity
python3 fixme/benchmark/validate_validity.py
```

The runner now emits identical literal TB vectors directly; the historical first-attempt `$random` benches remain in evidence. The validator uses saved evidence only and checks plan hashes, diff hashes, actual property counts, event/log presence, timeout classification, same-input cross-simulator decisions/counts and isolation probes. It derives `metrics.json` and `selected_trials.csv` without rerunning tools. It does not turn observed proof success into property adequacy. Execution is intentionally stopped at this bounded sample; broader independent-oracle construction, sequential/temporal semantics and random sampling remain open work.

## Archived upstream parser provenance

`upstream_parser/` contains byte-for-byte copies of the actually imported `src/simulation/vcs_runner.py` and its `simulation_base.py` dependency from the existing local official checkout. `provenance.json` records the pinned commit, repository paths, SHA256 and git blob IDs. These are review snapshots, not modified evaluators or a claim that VCS was executed. No upstream network access was used for this archival correction.
